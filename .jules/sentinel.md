## 2025-03-09 - [HIGH] Fix timing attack in server authentication
**Vulnerability:** The server authentication mechanism in `packages/server/src/auth.ts` used a non-constant time string comparison (`===`) to check the user's password against the expected password. This allows an attacker to measure the time it takes for the server to reject a login attempt, enabling them to guess the password character by character.
**Learning:** String comparisons in JavaScript/TypeScript short-circuit, which is inherently insecure for cryptographic or authentication-related comparisons. Additionally, `crypto.timingSafeEqual` throws an error if the two buffers are of unequal length, which must be handled without leaking the length through execution time.
**Prevention:** Always use `crypto.timingSafeEqual` for comparing secrets, tokens, or passwords. When dealing with potentially varying input lengths, perform a dummy comparison on the expected value if the lengths do not match, to ensure constant execution time regardless of whether the password matches or not.
